Thread 01

Measure

Does a score mean what it appears to mean — and would we notice if it didn’t?

Benchmarks built to be audited rather than trusted: per-problem provenance, verifier-checkable answers, and a stated limit on what the number supports.

  1. WirelessMathBench-XL: An Auditable Benchmark for Wireless Mathematical Reasoning

    NeurIPS 2026Xin Li, Mengbing Liu, Yiyang Zhu, Wenhe Zhang, Li Wei, Jiancheng An, Chau Yuen

    4,027 problems drawn from 836 arXiv papers across 20 wireless subfields, and frontier models cluster at 86.5–91.3%. It ships per-problem 13-gram contamination-overlap evidence against public pretraining text — a rerunnable audit of one lexical channel, not a proof that the benchmark is clean.

    Homepage arXiv

  2. Local Success Does Not Compose: Benchmarking Large Language Models for Compositional Formal Verification

    ICLR 2026Xu Xu*, Xin Li*, Xingwei Qu, Jie Fu, Binhang Yuan

    A model can verify a function on its own and still fail once the specifications have to fit together. The benchmark measures the distance between those two results.

    This one could as easily sit under Compose — it is a paper about composition failing. It is here because what it contributes is the measurement.

    Homepage OpenReview arXiv

  3. RobustMAD: Evaluating Real-World Robustness of Multimodal Small Language Models for Deployable Anomaly Detection Assistants

    TMLR 2026Anushiya Arunan, Xin Li, Yan Qin, U-Xuan Tan, Nhu Khue Vuong, Xiaoli Li, Chau Yuen

    Small multimodal models are offered as deployable anomaly-detection assistants. This measures which of them is still an assistant once the inputs are degraded the way deployment degrades them.

    Homepage OpenReview Code

  4. WirelessMathBench: A Mathematical Modeling Benchmark for LLMs in Wireless Communications

    Findings of ACL 2025Xin Li, Mengbing Liu, Li Wei, Jiancheng An, Mérouane Debbah, Chau Yuen

    The first benchmark for LLM mathematical reasoning in wireless communications, and where this thread started. WirelessMathBench-XL is its successor.

    Homepage arXiv

Thread 02

Train

Can we reward the reasoning we are able to check, rather than the answer we hope for?

Reinforcement learning, on-policy distillation and verifier-guided selection — all pointed at rewards a machine can confirm instead of rewards a rater approves.

  1. Re:Form: Reducing Human Priors in Scalable Formal Software Verification with RL in LLMs: A Preliminary Study on Dafny

    TMLR 2026Chuanhao Yan*, Fengdi Che*, Xuhan Huang*, Xu Xu*, Xin Li*, Yizhi Li*, Xingwei Qu*, …, Jie Fu

    RL for formal software verification with the hand-built scaffolding cut back: the reward is a Dafny proof that checks, so the signal does not depend on anyone’s opinion of the answer.

    OpenReview arXiv Code

  2. Beyond Teacher Assignment: Domain-Normalized Multi-Teacher On-Policy Distillation

    arXiv 2026Xin Li, Hao Jiang, Xin Gao, Annan Wang, Yuchen Xie, Jinghao Guo, Xingwei Qu, Yichi Zhang, Chau Yuen

    Routing decides which teacher supervises a prompt, but not how much that teacher’s feedback counts. Normalizing the scale per domain adds 1.2–3.1 points over label routing, across 2B, 4B and 9B students.

    Homepage arXiv Code Data Models

  3. TLVC

    Findings of EMNLP 2026

    On picking the right verifier for best-of-K reasoning selection.

    Homepage

Thread 03

Compose

When several models work together, does the interaction help — or quietly destroy answers that were already right?

What the models send each other, what they keep, and what the aggregate loses. This is the thread that sends work back to 01.

  1. Measuring Collapse and Correction in Homogeneous-Panel LLM Debate

    NeurIPS 2026Xin Li*, Mengbing Liu*, Chau Yuen

    Debate moves answers in both directions. Across 6,925 logged MMLU-Pro debates there are 253 collapses; a probe-gated freeze prevents 29 of them and gives up 108 corrections, which is net −79 under equal weights. Judged on collapse prevention alone it looks like a win. 58.9% of collapses begin in the first round.

    Homepage

  2. LACP: LLM Agent Communication Protocol Requires Urgent Standardization

    AI4NextG @ NeurIPS 2025Xin Li, Mengbing Liu, Chau Yuen

    A position paper: the protocol LLM agents use to talk to each other should be standardized now, while it is still cheap to change.

    Homepage arXiv

  3. GraphReduce: Coverage-Preserving LLM Aggregation for E-commerce Review Insights

    EMNLP Industry Track 2026Hao Jiang, Xin Li, Yichi Zhang, Weisi Lin

    Aggregating many reviews with an LLM is useful exactly as long as the aggregate still covers what the reviews said. This builds the aggregation so that coverage is preserved rather than assumed.

    An industry paper, and the applied one in this thread. It is here because the failure mode is the one this thread is about: an aggregate that quietly loses what was already there.

    Homepage
